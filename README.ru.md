# ZITI-GUI

[English version](README.md)

Трей + окно для управления **ziti-edge-tunnel** (туннелер OpenZiti) в Linux:
старт/стоп сервиса, вкл/выкл каждой идентичности, регистрация новых из JWT,
просмотр всех сервисов Ziti с intercept-адресами — по мотивам Ziti Desktop
Edge из [гайда для macOS](https://netfoundry.io/docs/openziti/how-to-guides/tunnelers/macos/),
но для Linux.

Чистый Go, без встраивания интерпретаторов: окно — [Gio](https://gioui.org)
(нативный Wayland **и** X11), трей — `fyne.io/systray` (StatusNotifierItem
поверх D-Bus), диалоги файлов — `zenity` с запасным `xdg-desktop-portal`.

## Возможности

**Окно** (открывается при старте; повторный запуск фокусирует существующее):

- шапка с живой точкой статуса и кнопками Запустить / Остановить /
  Перезапустить / *Зарегистрировать JWT…*;
- карточки идентичностей слева с переключателями вкл/выкл (сохраняются между
  перезапусками), статусом, числом сервисов, предупреждениями MFA/авторизации;
- справа — сервисы выбранной идентичности: имя, **все** intercept-адреса с
  портами, режим dial/bind. Клик по адресу копирует имя сервера в буфер
  (если адресов несколько — кликни нужный);
- подвал: версии, состояние IPC, кнопка журнала сервиса.

**Трей** (StatusNotifierItem): цветная иконка (зелёная — работает, оранжевая —
работает, но IPC недоступен, жёлтая — запускается, серая — остановлен,
красная — сбой), те же действия, подменю по каждой идентичности,
диагностика, журнал, выход.

**Внутри**

- вкл/выкл идентичностей применяется на живую через IPC туннелера
  (`on_off_identity`) и сохраняется: рестарт сервиса восстанавливает выбор;
- контексты, не инициализировавшиеся при старте сервиса (например, сеть ещё
  не готова), обнаруживаются автоматически и через ~20 с переинициируются;
- один экземпляр: повторный запуск бинарника фокусирует уже открытое окно;
- каждое действие пишется в журнал.

## Требования

- Linux, `systemd` (туннелер ожидается запущенным как **системный сервис** —
  так его ставят официальные пакеты `ziti-edge-tunnel` deb/rpm);
- Go **1.25+** для сборки;
- зависимости сборки Gio (cgo-биндинги): `gcc`, `pkg-config` и библиотеки
  ниже (рантайм-библиотеки обычно уже установлены);

| Debian / Ubuntu | Fedora | Arch |
|---|---|---|
| `libxkbcommon-dev libxkbcommon-x11-dev libx11-dev libx11-xcb-dev libxcursor-dev libxfixes-dev libwayland-dev libegl-dev` | `libxkbcommon-devel libxkbcommon-x11-devel libX11-devel libxcb-devel libXcursor-devel libXfixes-devel wayland-devel mesa-libEGL-devel` | `libxkbcommon libxkbcommon-x11 libx11 libxcb libxcursor libxfixes wayland mesa` |

- в рантайме: `polkit` (+ агент аутентификации) и **либо** `zenity`,
  **либо** `xdg-desktop-portal` для диалога выбора JWT; панель с поддержкой
  трея (GNOME/KDE, waybar, DankMaterialShell, …), чтобы видеть иконку;
- `wl-clipboard` опционален (дополнительный фолбэк буфера под Wayland).

## Сборка и запуск

```sh
go build -o ziti-gui .
./ziti-gui                # трей + окно
./ziti-gui --once         # один опрос статуса в JSON (для отладки)
./ziti-gui --identity-dir ~/.ziti/identities --service ziti-edge-tunnel.service
./ziti-gui --version
```

## Как это работает

GUI рассчитан, что туннелер работает как **systemd-сервис** (по умолчанию
`ziti-edge-tunnel.service`, пакетная раскладка: бинарник в `/opt/openziti/bin`,
идентичности в `/opt/openziti/etc/identities`, IPC-сокет в `/tmp/.ziti/`).
Всё определяется автоматически и переопределяется флагами или
`~/.config/ziti-gui/config.json`:

```json
{
  "identity_dir": "/opt/openziti/etc/identities",
  "service": "ziti-edge-tunnel.service",
  "ziti_bin": "",
  "poll_sec": 3,
  "disabled": {}
}
```

- **управление сервисом** — `pkexec systemctl start/stop/restart …`;
- **статусы** — команда туннелера `dump` поверх его IPC-сокета; парсинг
  толерантный (актуальный текстовый формат v1.18.x и старые JSON-варианты);
- **вкл/выкл** — `on_off_identity` на живую + сохранение в конфиг (запись
  только после успешной команды), повторное применение после рестартов
  сервиса и поздней загрузки контекстов;
- **регистрация** — `add` (enroll + загрузка в работающий туннелер, токен
  передаётся содержимым); при остановленном сервисе — `enroll` во временный
  файл, затем разовый `pkexec install` в каталог идентичностей и
  автоматический рестарт сервиса;
- **удаление** — IPC `delete` + удаление файла через `pkexec`
  (подтверждение в два клика).

## Первоначальная настройка

Из коробки IPC и каталог идентичностей принадлежат сервисному пользователю
(`ziti`), и GUI их не видит. В трее/окне появится пункт **«Настроить доступ
(пароль один раз)»** — он выполняет один `pkexec`-скрипт, который:

1. добавляет вашего пользователя в группу `ziti` (полностью — после
   перелогина);
2. выдаёт ACL на `/tmp/.ziti`, его сокеты и каталог идентичностей для
   текущей сессии;
3. ставит polkit-правило (`/etc/polkit-1/rules.d/50-ziti-gui.rules`),
   разрешающее старт/стоп/рестарт сервиса туннелера **без пароля**.

После этого трей полностью самостоятелен: рутинные действия без запросов.

## Автозапуск

Рекомендуемый способ — systemd **user-юнит** (см. `deploy/ziti-gui.service`,
поправьте путь к бинарнику):

```sh
mkdir -p ~/.config/systemd/user
cp deploy/ziti-gui.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now ziti-gui.service
journalctl --user -u ziti-gui -f     # логи GUI
```

Так GUI стартует вместе с сеансом, переживает падения (`Restart=always`) и не
наследует `no_new_privs` от песочниц (иначе setuid-`pkexec` откажется
работать — GUI предупредит). Пункт трея «Выход» останавливает юнит, чтобы
`Restart=always` не поднял процесс заново. Альтернативы: `spawn-at-startup`
в `config.kdl` niri или автозапуск среды.

## Про DNS

Туннелер перехватывает DNS для зити-имён (диапазон по умолчанию
`100.64.0.0/10`). Две ловушки:

- ему нужен реальный **upstream** для всех остальных имён; если resolv.conf
  указывает только на перехватчик (так делают некоторые инструменты),
  резолвинг зацикливается и умирает. Лечение: добавить
  `--dns-upstream=<DNS вашей сети>` в сервис, например дроп-ином:

  ```ini
  # /etc/systemd/system/ziti-edge-tunnel.service.d/dns.conf
  [Service]
  ExecStart=
  ExecStart=/opt/openziti/bin/ziti-edge-tunnel run --verbose=info \
    --dns-ip-range=100.64.0.1/10 --dns-upstream=192.168.1.1 \
    --identity-dir=/opt/openziti/etc/identities
  ```

- инструменты, прописывающие свой nameserver в
  `[global-dns-domain-*]` NetworkManager (например, остаток другого
  VPN-клиента), могут направить всю систему на адрес перехватчика; при
  остановленном туннелере DNS умрёт вместе с ним. Вторым сервером в этом
  списке стоит прописать DNS вашей сети — появится фолбэк.

## Если что-то не так

- **Нет иконки в трее** — панель должна поддерживать StatusNotifierItem
  (модуль `tray` в waybar, панели GNOME/KDE, DankMaterialShell, …). Дубль
  иконки после жёсткого kill — кэш оболочки: перезапустите панель
  (`dms restart`, `pkill waybar && waybar &`, …).
- **`wl_display.connect failed`** — GUI стартовал раньше графического
  сеанса. Приложение само находит wayland-сокет и ретраит; на X11
  использует `DISPLAY`.
- **Контекст не поднялся после рестарта** — GUI сам переинициирует зависшие
  контексты (~20 с); то же делает ручной выкл/вкл на карточке.
- **«IPC недоступен»** — нажмите «Настроить доступ»; это вопрос прав
  (группа `ziti` + ACL), а не неисправность туннелера.

## Отладка

```sh
./ziti-gui --once                    # снимок статуса без трея
go test ./...                        # тесты парсера dump

go run ./porttest                    # сырой тест FileChooser портала
```

## Структура проекта

```
main.go     флаги, конфиг, single-instance блокировка
tray.go     меню и действия трея
window.go   окно Gio (идентичности, сервисы, копирование в буфер)
state.go    модель статуса, парсинг dump, IPC-действия
ziti.go     обёртки systemd / ziti-cli
portal.go   D-Bus: выбор файла, уведомления
setup.go    первоначальная настройка доступа, диагностика
icons.go    иконки трея, рисуемые кодом
deploy/     systemd user-юнит
porttest/   отладочный зонд портала (в рантайме не нужен)
```
